Parte 1

Las reglas

5 min

Las reglas son la única barrera real de tus datos: la configuración de Firebase va dentro de la app y cualquiera puede leerla. Las que tienes publicadas son las de antes del catálogo, así que hay que reemplazarlas por estas.

  1. Firestore → Reglas → borrar → pegar → Publicar console.firebase.google.com › Firestore Database › Reglas

    Reemplazar, no añadir. Selecciona todo lo que haya en el editor, bórralo, y pega esto.

    firestore.rules
    rules_version = '2';

// Cada persona ve lo suyo y nada más, salvo lo que ponga en el estante.
//
// Esta es la única barrera real: la configuración de Firebase es pública, así
// que sin estas reglas cualquiera podría leer y escribir en la base de datos.
service cloud.firestore {
  match /databases/{database}/documents {

    // Quién vive en la casa. Se lee para saber si puedes tocar el estante, y
    // **no se escribe desde la app**: los uid se ponen a mano en la consola de
    // Firebase. Si se pudiera escribir desde aquí, cualquiera con una cuenta de
    // Google se metería solo.
    function deLaCasa() {
      return request.auth != null
        && request.auth.uid in get(/databases/$(database)/documents/casa/miembros).data.uids;
    }

    match /casa/miembros {
      allow read: if request.auth != null;
      allow write: if false;
    }

    // Todo lo de una persona cuelga de su identificador de sesión.
    match /gente/{uid}/{documento=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

    // El estante de la casa. Lo lee cualquiera de la casa; cada quien solo
    // puede poner y quitar lo suyo, y lo suyo es lo que lleva su uid en `de`.
    match /estanteria/{libro} {
      allow read: if deLaCasa();
      allow create: if deLaCasa() && request.resource.data.de == request.auth.uid;
      allow update: if deLaCasa()
                    && resource.data.de == request.auth.uid
                    && request.resource.data.de == request.auth.uid;
      allow delete: if deLaCasa() && resource.data.de == request.auth.uid;
    }

    // Lo que no encaje arriba, se deniega. Sin excepciones y sin silencios.
    match /{documento=**} {
      allow read, write: if false;
    }
  }
}
    El botón Publicar está arriba a la derecha. Si está apagado es que no detectó cambios: comprueba que de verdad reemplazaste el texto.
  2. Storage → Reglas → lo mismo console.firebase.google.com › Storage › Reglas
    storage.rules
    rules_version = '2';

// Los PDF de cada persona, y solo los suyos. Más el estante de la casa.
service firebase.storage {
  match /b/{bucket}/o {

    // La lista de la casa vive en Firestore: aquí se consulta, no se duplica.
    // Dos listas acaban diciendo cosas distintas.
    function deLaCasa() {
      return request.auth != null
        && request.auth.uid in firestore.get(/databases/(default)/documents/casa/miembros).data.uids;
    }

    match /gente/{uid}/{archivo=**} {
      allow read: if request.auth != null && request.auth.uid == uid;
      // Un tope por archivo: sin él, un fallo subiendo en bucle sale caro, y
      // Blaze no corta solo (D-12).
      allow write: if request.auth != null
                   && request.auth.uid == uid
                   && request.resource.size < 300 * 1024 * 1024;
    }

    // El estante: lo lee cualquiera de la casa y lo escribe cualquiera de la
    // casa. Quién puso qué se controla en Firestore, que es donde está el dato;
    // aquí solo hay bytes y no se puede saber de quién es un PDF.
    match /casa/libros/{archivo} {
      allow read: if deLaCasa();
      allow write: if deLaCasa() && request.resource.size < 300 * 1024 * 1024;
    }

    match /{archivo=**} {
      allow read, write: if false;
    }
  }
}

    Borra, pega, Publicar. Espera a ver el aviso de publicado con la fecha de hoy.

Parte 2

La casa

5 min

Todo PDF que suba cualquiera va a un catálogo común, y la estrella decide qué hay en la estantería de cada quien. Para que exista hay que apuntar quiénes sois, y eso se pone a mano: si la app pudiera añadir miembros, cualquiera con una cuenta de Google se metería solo.

  1. Entrad los dos en Vellum, una vez

    Cada persona pulsa Ajustes → Entrar con Google al menos una vez. Hasta que no entra, Firebase no le ha dado identificador y no hay nada que apuntar.

    Abrir Vellum ↗
  2. Copia los dos identificadores

    El atajo: ya los tienes. En Firestore → Datos, dentro de la colección gente hay un documento por persona, y el nombre de cada documento es su identificador. Son dos cadenas de 28 caracteres.

    console.firebase.google.com › Firestore Database › Datos
    Si la lista los corta con puntos suspensivos, toca el documento: el nombre entero sale arriba, en la ruta. También están en Authentication → Users, en la columna Identificador de usuario.

    Cópialos los dos donde puedas pegarlos luego: una nota del teléfono sirve.

  3. Crea la colección «casa» console.firebase.google.com › Firestore Database › Datos

    Pulsa Iniciar colección. ID de la colección:

    ID de la colección
    casa

    Te pedirá el primer documento. ID del documento (no dejes que lo genere solo, escríbelo):

    ID del documento
    miembros
  4. Un solo campo, con los dos identificadores

    Campo uids, tipo array. Aparece debajo un elemento 0: ponle tipo string y pega el primer identificador en la caja String.

    Aquí es donde todo el mundo se enreda. Para el segundo identificador hay que pulsar el «Agregar campo» de dentro — el que está indentado, alineado con el 0 — y no el de más abajo a la izquierda. El de abajo añade otro campo al documento; el de dentro añade otro elemento al array, que es lo que quieres.

    Sabrás que acertaste porque aparece un 1 debajo del 0, con su propio selector de tipo. Ponle string y pega el segundo.

    Tiene que quedar así antes de guardar:

    CampoTipoValor
    uidsarray—
    0stringel identificador de una persona
    1stringel de la otra
    Y que ninguna caja quede vacía. La estructura puede estar perfecta y no servir de nada si el String se queda en blanco.
    Los tres nombres, exactos y en minúsculas: casa, miembros, uids. Las reglas buscan justo eso y no hay margen.
  5. Sincroniza en los dos aparatos

    En Vellum, Ajustes → Sincronizar ahora. Al volver a la estantería tienen que aparecer dos pestañas arriba: Mi estantería y Toda la casa.

    En «Toda la casa» salen los libros de los dos, cada uno con un círculo y la inicial de quien lo subió, y una estrella debajo para traértelo a tu estantería. Si no aparecen las pestañas, casi siempre falta un uid o algún nombre no está en minúsculas.
Parte 3

El apagón

15 min

El presupuesto de un dólar que pusiste avisa pero no corta: manda un correo y la factura sigue subiendo. Esto corta de verdad — cuando el gasto pasa de un dólar, le quita al proyecto la cuenta de facturación.

Cuando salte pierdes las subidas de PDF. Leer, traducir y el progreso siguen igual, porque todo está también en el aparato.

  1. Abre Cloud Shell console.cloud.google.com

    Comprueba arriba que el proyecto es infiniity-vellum. Pulsa el icono de terminal >_ arriba a la derecha: es una consola dentro del navegador, no hay que instalar nada. La primera vez tarda un minuto y pide autorizar.

  2. Enciende las piezas y crea el canal
    Pega esto entero
    gcloud services enable \
  cloudfunctions.googleapis.com run.googleapis.com cloudbuild.googleapis.com \
  eventarc.googleapis.com artifactregistry.googleapis.com \
  pubsub.googleapis.com cloudbilling.googleapis.com billingbudgets.googleapis.com

gcloud pubsub topics create presupuesto-vellum

    Tarda un par de minutos y no dice gran cosa. Si acaba sin errores, listo.

  3. Sube los dos archivos del vigía

    Están en el repositorio, en la carpeta apagon/: index.js y package.json. En Cloud Shell, tres puntos ⋮ arriba a la derecha → Subir. Luego colócalos:

    Ordenarlos
    mkdir -p ~/apagon && mv ~/index.js ~/package.json ~/apagon/ && ls ~/apagon
    Debe responder index.js package.json.
  4. Publica la función
    Desplegar
    gcloud functions deploy apagon-vellum \
  --gen2 --runtime=nodejs24 --region=us-central1 \
  --trigger-topic=presupuesto-vellum \
  --entry-point=apagon \
  --set-env-vars TOPE=1,PROYECTO_VIGILADO=infiniity-vellum \
  --source=./apagon
    Si se queja de nodejs24 es que Google lo retiró: gcloud functions runtimes list dice cuáles hay, y sirve el Node más nuevo.
  5. Dale permiso para cortar

    Sin esto se despierta y no puede hacer nada. Primero, mira con qué identidad corre:

    Ver su identidad
    gcloud functions describe apagon-vellum --gen2 --region=us-central1 \
  --format='value(serviceConfig.serviceAccountEmail)'

    Te devuelve un correo acabado en .gserviceaccount.com. Cópialo, ve a facturación → pestaña Permisos, y añádelo con el rol Administrador de la cuenta de facturación.

    console.cloud.google.com/billing
    Sí, es un rol fuerte. Es el único que permite desenganchar la facturación. Por eso la función no hace nada más: lee un número y, si se pasa, desengancha.
  6. Conecta el presupuesto al canal

    En Facturación → Presupuestos y alertas, abre el presupuesto de 1 dólar (o créalo: ámbito solo infiniity-vellum, 1 USD, mensual, umbrales al 50 %, 90 % y 100 % del gasto real).

    Baja a Gestionar notificaciones y marca «Conectar un tema de Pub/Sub a este presupuesto». Elige presupuesto-vellum. Guarda.

    Este paso es el que une las dos mitades. Sin él la función existe pero nadie la llama.
  7. Comprueba que está viva
    Ensayo
    gcloud pubsub topics publish presupuesto-vellum \
  --message='{"costAmount":0.10,"budgetAmount":1,"currencyCode":"USD"}'
sleep 20
gcloud functions logs read apagon-vellum --region=us-central1 --limit=5

    Tiene que salir «Va por 0.1 USD, el tope es 1. Nada que hacer.» Si sale eso, la cadena entera funciona.

    No pruebes con un número mayor que 1. La función haría su trabajo y te dejaría el proyecto sin facturación de verdad.

Lo que solo se sabe usándola

Hay 262 comprobaciones automáticas, y ninguna cubre esto. No es trabajo pendiente: es la parte que solo se comprueba leyendo. Ve marcando cuando lo veas funcionar.

  • Entrar con Google de verdad. Lo primero, porque desbloquea el resto.
  • Que los dos os veáis. Sube un PDF en un aparato y búscalo en el otro, en «Toda la casa».
  • El sonido y la vibración al pasar página, en el teléfono.
  • Sin internet. Pon el avión y abre la app: tiene que abrir y dejarte leer.
  • Un cómic pesado de verdad. Los PDF de prueba pesan kilobytes. Vigila cuánto tarda en subir y cuánto ocupa.
  • Pellizcar y seleccionar con los dedos. Los gestos se prueban simulados, no con dedos.
  • Si Gemini traduce bien. La API está simulada en las pruebas: se comprueba el cliente, no la calidad.
