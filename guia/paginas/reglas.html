Encender la nube

Dos cosas que solo puedes hacer tú, porque son de tu cuenta y no del código. Sin ellas, «Entrar con Google» se abre y falla.

El portero Autorizar el dominio de la app en Firebase, para que Google acepte abrir la sesión desde ahí. Sin esto: la ventana se abre y se cierra sola.
Las reglas Publicar quién puede leer y escribir. Están escritas en el repositorio; falta subirlas a tu proyecto. Sin esto: entras, pero nada se sincroniza.
¿Por qué no lo hago yo? Las dos tocan la configuración de tu cuenta de Google, no el código de la app. Publicarlas desde aquí necesitaría una credencial tuya con permiso para cambiar tu proyecto, y esa credencial no debería salir nunca de tu máquina.
Parte A

El portero

2 min

Firebase solo deja abrir sesión desde direcciones que tú apruebas. La de Vellum todavía no está en esa lista.

  1. Abre Authentication en tu proyecto console.firebase.google.com › infiniity-vellum › Authentication

    Si el enlace te deja en otro sitio: en el menú de la izquierda, Compilación → Authentication, y arriba la pestaña Settings (o Configuración).

    Si Authentication te pide activarse, pulsa Comenzar y habilita el proveedor Google. Es el único que usa Vellum.
  2. Añade el dominio de la app

    Busca Dominios autorizados (Authorized domains), pulsa Agregar dominio y escribe exactamente:

    El dominio
    infiniity-eventos.github.io
    Sin https:// y sin la carpeta del final. Solo el dominio. Si pegas la dirección entera te lo rechaza.
Parte B

Las reglas

6 min

Las reglas son la única barrera real de tus datos. La configuración de Firebase es pública por diseño —va dentro de la app, cualquiera puede leerla— así que lo que impide que un desconocido escriba en tu base de datos es exactamente esto. Por eso deniegan todo salvo lo tuyo.

  1. Abre las reglas de Firestore console.firebase.google.com › Firestore Database › Reglas

    Si Firestore todavía no existe, te ofrecerá crearlo: elige modo de producción (denegar todo) y la región que te proponga. El modo da igual, porque lo siguiente que haces es reemplazar las reglas.

  2. Borra lo que haya y pega esto

    Selecciona todo el contenido del editor y bórralo. Luego pega. Reemplazar, no añadir: si dejas las reglas viejas debajo, Firebase se queda con la primera que encaje y el resultado no es el que esperas.

    firestore.rules
    rules_version = '2';

// Cada persona ve lo suyo y nada más.
//
// Esta es la única barrera real: la configuración de Firebase es pública, así
// que sin estas reglas cualquiera podría leer y escribir en la base de datos.
service cloud.firestore {
  match /databases/{database}/documents {

    // Todo lo de una persona cuelga de su identificador de sesión.
    match /gente/{uid}/{documento=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

    // Lo que no encaje arriba, se deniega. Sin excepciones y sin silencios.
    match /{documento=**} {
      allow read, write: if false;
    }
  }
}
  3. Pulsa «Publicar»

    El botón está arriba a la derecha del editor. Tarda un momento y luego dice que las reglas están publicadas, con la fecha.

    Si el botón está apagado es que no ha detectado cambios: comprueba que de verdad reemplazaste el texto.
  4. Ahora las de Storage, igual console.firebase.google.com › Storage › Reglas

    Si Storage no está activado, actívalo ahora: es el que guarda los PDF, y necesita Blaze, que ya tienes.

    storage.rules
    rules_version = '2';

// Los PDF de cada persona, y solo los suyos.
service firebase.storage {
  match /b/{bucket}/o {

    match /gente/{uid}/{archivo=**} {
      allow read: if request.auth != null && request.auth.uid == uid;
      // Un tope por archivo: sin él, un fallo subiendo en bucle sale caro, y
      // Blaze no corta solo (D-12).
      allow write: if request.auth != null
                   && request.auth.uid == uid
                   && request.resource.size < 300 * 1024 * 1024;
    }

    match /{archivo=**} {
      allow read, write: if false;
    }
  }
}

    Borra, pega, Publicar.

Comprobar

Si funcionó, lo verás

Abre Vellum, ve a Ajustes → Tu cuenta y pulsa Entrar con Google.

✓Sale tu nombre y tu correo, y debajo dice que está sincronizando. Ya está: el progreso y las etiquetas empiezan a viajar solos, y los PDF suben cuando estés en wifi.
✕«Este dominio no está autorizado» — falta la parte A, o el dominio se escribió con https:// delante.
✕Entras, pero dice que no pudo sincronizar — faltan las reglas, o se publicaron en un proyecto distinto. Comprueba arriba en la consola que pone infiniity-vellum.
✕La ventana se abre y se cierra sin más — casi siempre es el bloqueador de ventanas emergentes del navegador. Permítelas para esta página y vuelve a intentarlo.
Alternativa

Desde la PC, en un comando

Si prefieres no tocar la consola web y tienes el repositorio clonado en tu Fedora, la parte B se hace de una vez. La parte A no: los dominios autorizados solo se tocan a mano.

En la carpeta del proyecto
npx firebase login
npx firebase deploy --only firestore:rules,storage

La primera orden abre el navegador para que inicies sesión. La segunda lee firebase.json, que ya apunta a los dos archivos, y los publica en infiniity-vellum.
